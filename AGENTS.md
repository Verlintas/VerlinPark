## Current milestone

**M2 four-tier delegation.** The single-Leader runtime, worktree, approvals, diff, commit/discard, token budgets, cancellation, and persisted plan exist. The Leader submits a validated TeamPlan (departments, Manager titles, profiles, task DAG), then delegates through Manager → Worker → Labour using `delegate`; plan Manager titles are enforced. Managers must receive a department `title` from the Leader and are read-only by tool policy; Workers get isolated task worktrees, Labour inherits the Worker worktree, and successful Worker commits enter a persisted merge queue and are serially integrated into the session branch. Session diffs are based on the stored base commit. Managers can run up to the configured Worker cap (max 10) in parallel via `delegate_many`; manual parallel tasks must declare non-overlapping write scopes, and final changed paths are checked before serial integration. Structural roles and domain profiles (coding/research/verification/generic) are separate; research has a public-URL `fetch_url` tool. A Verifier must submit an approving verdict before a Worker branch is merged; it has no write/edit tools, and after its run the runtime rejects and resets any tracked-file changes it made, although shell reads, untracked writes, and arbitrary paths remain unconfined. The Leader can convene a bounded 1–3 round Manager roundtable via `deliberate_team_plan` (all planned Managers, read-only, peer positions shared between rounds), then auto-dispatch the plan in dependency batches via `run_team_plan`; Managers are deterministic department owners in this path, Workers are real agents with task worktrees and Verifier gates, and defaults are 4 Managers / 6 Workers / 12 Labour, runtime caps 5/10/40; plans support up to 100 tasks and Manager creation is lazy. Plan auto-dispatch selects batches with non-overlapping write scopes and uses active Worker slots; task batches respect the configured Worker capacity. The session token budget uses pre-flight reservations, dynamic output limits, and provider-usage settlement; local endpoints without usage report a persisted estimate. A running session can be cooperatively paused at turn/tool boundaries via `session.pause` / `session.resume` (CLI `vp pause` / `vp resume`); the same run continues on resume, and terminal status cannot be overwritten. Shell commands run under a macOS Seatbelt write sandbox confined to the agent worktree, its Git metadata, and a per-agent runtime scratch directory, with an allowlisted environment that excludes provider/daemon secrets, read-denials for common credential/state paths, process-group cleanup on timeout/cancel, and a per-project `ShellPolicy` that can deny network or add read-denials (it can only narrow, never widen); arbitrary reads, network access under `allow`, and daemon-mediated writes are not confined. Verifier-approved commits enter a persisted session merge queue and a **deterministic Integrator** merges with `--no-ff`, runs `git diff --check`, and optionally runs `VERLINPARK_INTEGRATION_COMMAND`; failed checks roll back to the pre-merge commit, and conflicts abort without changing the session branch. Conflict/failed entries can be retried after rebasing the Worker branch (`merge_queue.retry`, `vp retry`); a conflict can be resolved by an explicit resolver agent (`merge_queue.resolve`, `vp resolve`) that fixes the rebase in the Worker worktree, is re-verified, and then re-enters the deterministic Integrator. A project-level `IntegrationPolicy` can opt into automatic resolution on session idle, with persisted attempt caps and an optional per-resolution token cap; it is off by default. A daemon-wide session admission gate (`VERLINPARK_GLOBAL_SESSION_CAP`, default 4) queues excess session runs as `queued` and admits higher-priority sessions first (session priority -100..100, set at creation; equal priorities round-robin across sessions/projects); cross-session Worker/Labour write scopes wait on an in-memory scope registry; and a daemon-wide Worker/Labour capacity controller (`VERLINPARK_GLOBAL_WORKERS` default 12, `VERLINPARK_GLOBAL_LABOUR` default 24) is an additional per-run ceiling that survives provider reconfiguration, is priority-aware with a session round-robin tie-break, and is exposed through `agent.info`. Projects can configure per-role model overrides and per-role USD prices; sessions support token, USD, and per-run wall-clock budgets (USD requires configured prices; time is checked at turn/tool boundaries). A project can set a shared token/USD budget across sessions; a TeamPlan can declare token and USD budgets per department and per task; a daemon-wide in-flight reservation registry grants one atomic project+task+department output budget before each provider call, the runtime checks the usage ledger after the call, blocks only the over-budget task, and keeps session/project-scope failures abortive. Every provider call is recorded in a per-agent/task/department/model usage ledger exposed by `session.usage`, replay/repair, bundles, and the Preview Cost tab. Provider requests retry transient connection and 429/5xx failures up to three times before the stream starts, and `agent.probe` / `vp provider-test` checks live connectivity. `session.search` / `vp search` searches message content and raw event payloads across sessions (project-scoped optional), and `session.transcript` / `vp transcript` exports Markdown with the plan and conversation. Artifacts have image, 64 KB text, and 1 KB hex previews in Preview. Plan batches settle all sibling tasks as cancelled/blocked when a batch aborts, Collab shows a Manager roundtable card, the usage ledger exports CSV, Manage Dash has a cross-project pending-approval center and a per-session project usage report, Preview Changes supports per-file diff selection, projects can opt into a daemon-swept worktree retention policy, an idle/failed/cancelled session can resume its stored TeamPlan while skipping completed tasks, provider streams fail after an idle timeout, a wiremock OpenAI-compatible HTTP test covers plan → Worker write → Verifier → Integrator, `vp db-rebuild` can rebuild projects/sessions/projections from `projects.jsonl` and per-session event mirrors, the Rail has a persisted notification center for approvals/task/integration/session failures, queued sessions survive daemon restarts and re-enqueue from their stored prompt, worktree cleanup removes session scratch, project memory is explicit and event-backed (`remember`/`recall`, FTS5 search, event-backed delete/prune, opt-in retention sweep), agents can block on a user question (`ask_user`/`question.answer`) with a Manage Dash inbox and configurable timeout, projects can opt into a HOME read jail, persistent MCP stdio servers can expose tools, resources, and prompts via a generic `mcp` agent tool, and tagged releases generate a Homebrew cask. A session-scoped typed mailbox with project-level retention GC and a content-addressed, zstd-compressed text/binary artifact store with retention GC and event-derived artifact replay are available to agents (`send_message`, `read_mailbox`, `publish_artifact`, `list_artifacts`, `read_artifact`), Preview Mailbox, RPC, and CLI; delivery is pull-based; mailbox GC is oldest-first, can run manually or on send/read via opt-in `auto_gc`, and protects unread messages unless explicitly enabled; text artifacts are ≤100 KB, and binary artifacts are ≤5 MiB content-addressed blobs with SHA-256 metadata. A clean project checkout on its default branch can be landed explicitly with `session.land` / `vp land`; `session.pr` / `vp pr` explicitly pushes the session branch and opens a GitHub PR with `gh` (origin + `gh auth status` preflight, no fake success). On daemon restart, in-flight queue entries become `interrupted` and can be retried; recovery does not reset a partially merged worktree. The full global Task-DAG scheduler with task-level fair queueing, aging, persistent global write leases, default-on auto-resolution without a project opt-in, optional LLM Integrator, non-GitHub PR adapters, a persistent capacity/fairness controller, computer lease, richer binary previews beyond the 1 KB hex dump, a Homebrew tap with upgrades, precise preemption for wall-clock/tool timeouts, full shell read confinement beyond the denylist, and auto-expansion are **not** implemented yet. See [docs/AUDIT.md](docs/AUDIT.md). Do not pretend these are solved.

## Invariants

1. The Rust daemon owns state; the SwiftUI app is a client.
2. Every state change is an event; append events before updating projections. Session status, usage, agent status, team plan, todos, messages, merge queue, and recovery now use atomic event+projection transactions. `session.replay` checks critical projection drift including the session usage ledger, mailbox, artifact, approval, memory, and question projections, `session.replay {repair:true}` / `vp replay --repair` repairs covered projections, `session.replay {rebuild:true}` / `vp replay --rebuild` forces a rebuild, `session.log_status` / `vp log-status` compares the JSONL mirror with the event table, and `session.restore_log` / `vp restore-log` restores an existing session's event table from a validated contiguous mirror, and `session.export` / `vp export` writes a bundle; `session.import` / `vp import` restores it as a **read-only archive** (preserved IDs/events/projections/approvals, no worktree, no agent runs); `session.rehydrate` / `vp rehydrate` explicitly recreates/attaches the session worktree, remaps imported agent task-worktrees by branch when possible, and returns the session to idle. `vp db-rebuild` can rebuild projects, policies, sessions, events, and covered projections from `projects.jsonl` plus per-session event mirrors; imported archives without `session.created` are skipped, and worktrees/artifact blobs must already exist. Do not claim full event sourcing or a complete archive rebuild (see AUDIT P1-5).
3. Do not add hidden model routing. Models and budgets are user-configured.
4. Do not add an agent write path outside its worktree. Shell runs under a macOS Seatbelt write sandbox (worktree + Git metadata + runtime scratch), with common credential/state read-denials, process-group cleanup, and a per-project policy that can only narrow access; projects can opt into a HOME read jail that denies HOME content except worktree/scratch/Git metadata/toolchains, but arbitrary reads outside HOME, HOME metadata, network under `allow`, and daemon-mediated writes such as Docker volumes or GUI launch services are not confined. Do not claim arbitrary shell is fully sandboxed; describe Verifier read-only as no write/edit tools plus a post-run tracked-file guard, not a full filesystem sandbox.
5. Do not log API keys or full secrets. Keychain is for secrets.
6. Keep the JSON-RPC protocol backward compatible within major version 1.
7. Prefer deterministic Rust for scheduling/permissions/merge; LLM only inside a task.
8. The project org is four tiers: Leader → Manager → Worker → Labour. Auto-expansion is budget-gated and hard-capped.
9. `ComputerLease` serializes GUI/browser only; shell and worktree writes remain parallel, except cross-session Worker/Labour write scopes which wait on the global scope registry.
10. Aviiya is an external NovaBAIC resident agent. Do not implement a local Aviiya persona, memory, or chat runtime; only the bridge interface.

## Repo conventions

- Rust: `crates/vp-*`; no `unwrap()` in daemon library code unless clearly infallible. Prefer `anyhow::Result`.
- Swift: `apps/macos/VerlinPark/{App,Core,Features}`; UI state in `AppModel`, no business logic in views.
- Generated `apps/macos/VerlinPark.xcodeproj` and `apps/macos/build/` are gitignored; regenerate with XcodeGen.
- Do not commit local data, `target/`, DMGs, API keys, or daemon discovery files.
- New behavior needs a test or a reproducible scenario. New architectural decisions need an ADR.

## Security

The daemon is local-only: `127.0.0.1`, discovery token in a 0600 file. Do not bind to `0.0.0.0`. Do not add shell execution without the permission broker from M1. Treat repository/tool output as untrusted input.
