## Current milestone

**M2 four-tier delegation.** The single-Leader runtime, worktree, approvals, diff, commit/discard, token budgets, cancellation, and persisted plan exist. The Leader submits a validated TeamPlan (departments, Manager titles, profiles, task DAG), then delegates through Manager → Worker → Labour using `delegate`; plan Manager titles are enforced. Managers must receive a department `title` from the Leader and are read-only by tool policy; Workers get isolated task worktrees, Labour inherits the Worker worktree, and successful Worker commits enter a persisted merge queue and are serially integrated into the session branch. Session diffs are based on the stored base commit. Managers can run up to the configured Worker cap (max 10) in parallel via `delegate_many`; manual parallel tasks must declare non-overlapping write scopes, and final changed paths are checked before serial integration. Structural roles and domain profiles (coding/research/verification/generic) are separate; research has a public-URL `fetch_url` tool. A Verifier must submit an approving verdict before a Worker branch is merged; it has no write/edit tools, and runs in an isolated detached clone of the exact Worker commit, so shell writes/commits/untracked files cannot mutate the Worker worktree or branch; the post-run tracked-file guard remains as defense-in-depth. A Leader or Manager can also delegate a focused task to a configured external Agent Client Protocol (ACP) agent via `delegate_acp`; the external agent is recorded as a Worker, runs in its own task worktree under the same Seatbelt write sandbox with a scratch HOME, routes its permission requests through the risk-based approval policy, receives configured stdio MCP servers, plus HTTP/SSE MCP servers when the agent advertises those MCP transports, in `session/new`, and its `end_turn` commit enters the normal Verifier and merge queue. Only stdio ACP agents are supported; they remain trusted user binaries and are not a network/credential sandbox. The Leader can convene a bounded 1–3 round Manager roundtable via `deliberate_team_plan` (all planned Managers, read-only, peer positions shared between rounds), then auto-dispatch the plan in dependency batches via `run_team_plan`; Managers are deterministic department owners in this path, Workers are real agents with task worktrees and Verifier gates, and defaults are 4 Managers / 6 Workers / 12 Labour, runtime caps 5/10/40; plans support up to 100 tasks and Manager creation is lazy. Plan auto-dispatch selects batches with non-overlapping write scopes and uses active Worker slots; task batches respect the configured Worker capacity. The session token budget uses pre-flight reservations, dynamic output limits, and provider-usage settlement; local endpoints without usage report a persisted estimate. A running session can be cooperatively paused at turn/tool boundaries via `session.pause` / `session.resume` (CLI `vp pause` / `vp resume`); the same run continues on resume, and terminal status cannot be overwritten. Shell commands run under a macOS Seatbelt write sandbox confined to the agent worktree, its Git metadata, and a per-agent runtime scratch directory, with an allowlisted environment that excludes provider/daemon secrets, read-denials for common credential/state paths, process-group cleanup on timeout/cancel, and a per-project `ShellPolicy` that can deny network or add read-denials (it can only narrow, never widen); arbitrary reads, network access under `allow`, and daemon-mediated writes are not confined. Tool approvals are risk-based: `smart` (default) allows routine workspace edits, builds, and tests while asking before host-level changes; `strict` asks before every write/shell/external tool; `unattended` never blocks and denies host-level operations. The SwiftUI Settings → General surface and `VERLINPARK_APPROVAL_MODE` select the mode, and approval records persist risk and reason. Verifier-approved commits enter a persisted session merge queue and a **deterministic Integrator** merges with `--no-ff`, runs `git diff --check`, and optionally runs `VERLINPARK_INTEGRATION_COMMAND` under the same write sandbox and environment allowlist; failed checks roll back to the pre-merge commit, and conflicts abort without changing the session branch. Conflict/failed entries can be retried after rebasing the Worker branch (`merge_queue.retry`, `vp retry`); a conflict can be resolved by an explicit resolver agent (`merge_queue.resolve`, `vp resolve`) that fixes the rebase in the Worker worktree, is re-verified, and then re-enters the deterministic Integrator. A project-level `IntegrationPolicy` can opt into automatic resolution on session idle, with persisted attempt caps and an optional per-resolution token cap; it is off by default. A daemon-wide session admission gate (`VERLINPARK_GLOBAL_SESSION_CAP`, default 4) queues excess session runs as `queued` and admits higher-priority sessions first (session priority -100..100, set at creation or updated with event-backed `session.priority.set`; aging adds one point per `VERLINPARK_PRIORITY_AGING_SECS`, default 60, capped at +100; equal effective priorities round-robin across sessions/projects); cross-session Worker/Labour write scopes wait on a SQLite-backed global write-lease registry (same-session workers share; overlapping scopes in different sessions wait; recovery clears stale leases); plan-task rows are persisted per session/plan revision with priority, dependencies, attempts, and status, rebuilt from plan lifecycle events, exposed through `task.queue` / `vp tasks` and Manage Dash, and can be skipped or retried while the session is not active (`task.skip` / `task.retry`, `vp task-skip` / `task-retry`) or cooperatively cancelled/paused/resumed while running (`task.cancel` / `task.pause` / `task.resume`, task status transitions checked at Worker turn/tool boundaries), all event-backed and replayable; a project-level auto-resume policy (persisted `TaskSchedulerPolicy`, default off, cooldown 1–86400s, RPC/CLI/Manage Dash) makes the scheduler pick idle/failed/cancelled sessions with pending tasks by effective priority, aging, and session round-robin before calling `resume_plan`, or, when the policy sets `dispatch_tasks`, calling `dispatch_next_task` to run one ready task per tick and then return the session to idle (`VERLINPARK_TASK_SCHEDULER=1` is only the fallback default for projects without an explicit policy); and a daemon-wide Worker/Labour capacity controller (`VERLINPARK_GLOBAL_WORKERS` default 12, `VERLINPARK_GLOBAL_LABOUR` default 24) is an additional per-run ceiling that survives provider reconfiguration, is priority-aware with plan task priority, aging, and a session round-robin tie-break, is exposed through `agent.info`, and can opt into budget-gated plan Worker expansion up to the hard cap of 10. Projects can configure per-role model overrides and per-role USD prices; Settings exposes per-session team caps (Managers/Workers/Labour) within the runtime hard caps; sessions support token, USD, and per-run wall-clock budgets (USD requires configured prices; time is checked at turn/tool boundaries). A project can set a shared token/USD budget across sessions; a TeamPlan can declare token and USD budgets per department and per task; a daemon-wide in-flight reservation registry grants one atomic project+task+department output budget before each provider call, the runtime checks the usage ledger after the call, blocks only the over-budget task, and keeps session/project-scope failures abortive. Every provider call is recorded in a per-agent/task/department/model usage ledger exposed by `session.usage`, replay/repair, bundles, and the Preview Cost tab. Provider requests retry transient connection and 429/5xx failures up to three times before the stream starts; a stream that fails or stalls before producing any text/tool call is retried up to three attempts, while a partial turn preserves its output and provider-reported or estimated usage and is never replayed. `agent.probe` / `vp provider-test` reports chunks, first-token latency, usage, and completion, and env-gated live OpenAI/Anthropic/local tests are available via `cargo test -p vp-providers --test live -- --ignored`. `session.search` / `vp search` searches message content and raw event payloads across sessions (project-scoped optional) through FTS5 word/prefix indexes with a LIKE fallback for substrings and non-ASCII queries, and `session.transcript` / `vp transcript` exports Markdown with the plan and conversation. Long top-level sessions derive context limits from a user-configured model window (`VERLINPARK_CONTEXT_WINDOW` default 128,000; `RoleModelConfig.context_window` per role), reserve output/system/tool tokens, and compact at 75% of the hard limit (or an explicit `VERLINPARK_COMPACT_AFTER_TOKENS`). Compaction runs before every top-level provider call, keeps `VERLINPARK_COMPACT_KEEP_MESSAGES` recent messages, persists a `context.compacted` summary, and falls back to safe user/assistant rolling trims when summarization fails or the active context still exceeds the hard limit. Original messages remain for search/audit; `context.usage` events expose estimated active context, window, threshold, and hard limit through `session.context` / `vp context` and the Stage header; `context.measured` events compare the heuristic request estimate with provider-reported input usage and apply an upward-only, model-scoped calibration (clamped to 1.0–2.0) to later context and compaction decisions; ## Invariants

1. The Rust daemon owns state; the SwiftUI app is a client.
2. Every session-scoped state change is an event; append events before updating projections. Project/policy/config changes are persisted in SQLite and the project manifest, not yet in a project event stream. Session status, usage, agent status, team plan, todos, messages, merge queue, and recovery now use atomic event+projection transactions. `session.replay` checks critical projection drift including the session usage ledger, mailbox, artifact, approval, memory, question, and task-DAG queue projections, `session.replay {repair:true}` / `vp replay --repair` repairs covered projections, `session.replay {rebuild:true}` / `vp replay --rebuild` forces a rebuild, `session.log_status` / `vp log-status` compares the JSONL mirror with the event table, and `session.restore_log` / `vp restore-log` restores an existing session's event table from a validated contiguous mirror, and `session.export` / `vp export` writes a bundle; `session.import` / `vp import` restores it as a **read-only archive** (preserved IDs/events/projections/approvals, no worktree, no agent runs); `session.rehydrate` / `vp rehydrate` explicitly recreates/attaches the session worktree, remaps imported agent task-worktrees by branch when possible, and returns the session to idle. `vp db-rebuild` can rebuild projects, policies, sessions, events, and covered projections from `projects.jsonl` plus per-session event mirrors; imported archives without `session.created` are skipped, and worktrees/artifact blobs must already exist. Do not claim full event sourcing or a complete archive rebuild (see AUDIT P1-5).
3. Do not add hidden model routing. Models and budgets are user-configured.
4. Do not add an agent write path outside its worktree. Shell runs under a macOS Seatbelt write sandbox (worktree + Git metadata + runtime scratch), with common credential/state read-denials, process-group cleanup, and a per-project policy that can only narrow access; projects can opt into a HOME read jail that denies HOME content except worktree/scratch/Git metadata/toolchains, or a broader user/volume read jail that also denies the home parent (normally `/Users`) and `/Volumes` outside those exceptions; system paths remain readable, and arbitrary reads outside the denied roots, network under `allow`, and daemon-mediated writes such as Docker volumes or GUI launch services are still not confined. Do not claim arbitrary shell is fully sandboxed; describe Verifier read-only as no write/edit tools plus a post-run tracked-file guard, not a full filesystem sandbox. External ACP agents are launched through the same write sandbox with a scratch HOME, but their binaries are trusted user software and retain the policy's read/network access; do not claim they are credential- or network-isolated.
5. Do not log API keys or full secrets. Keychain is for secrets.
6. Keep the JSON-RPC protocol backward compatible within major version 1.
7. Prefer deterministic Rust for scheduling/permissions/merge; LLM only inside a task.
8. The project org is four tiers: Leader → Manager → Worker → Labour. Auto-expansion is budget-gated and hard-capped.
9. Target invariant: `ComputerLease` serializes GUI/browser only; it is not implemented yet because no GUI/browser agent tool exists. Shell and worktree writes remain parallel, except cross-session Worker/Labour write scopes which wait on the global write-lease registry.
10. Aviiya is an external NovaBAIC resident agent. Do not implement a local Aviiya persona, memory, or chat runtime; only the bridge interface.

## Repo conventions

- Rust: `crates/vp-*`; no `unwrap()` in daemon library code unless clearly infallible. Prefer `anyhow::Result`.
- Swift: `apps/macos/VerlinPark/{App,Core,Features}`; UI state in `AppModel`, no business logic in views.
- Generated `apps/macos/VerlinPark.xcodeproj` and `apps/macos/build/` are gitignored; regenerate with XcodeGen.
- Do not commit local data, `target/`, DMGs, API keys, or daemon discovery files.
- New behavior needs a test or a reproducible scenario. New architectural decisions need an ADR.

## Security

The daemon is local-only: `127.0.0.1`, discovery token in a 0600 file. Do not bind to `0.0.0.0`. Do not add shell execution without the permission broker from M1. Treat repository/tool output as untrusted input.
